# Execution Context & Call Stack

---

## 1.1 What is an Execution Context?

> **Everything in JavaScript happens inside an Execution Context.**

When JavaScript starts running, **before any code executes**, an Execution Context (EC) is created. It is the environment in which JavaScript code is evaluated and executed.

An Execution Context has **two components**:

| Component            | Also Known As        | Description                                       |
| -------------------- | -------------------- | ------------------------------------------------- |
| **Memory Component** | Variable Environment | Stores variables and functions as key-value pairs |
| **Code Component**   | Thread of Execution  | Executes code one line at a time                  |

![Execution Context Diagram](/assets/execution_context_diagram.png)

> 💡 **JavaScript is a Synchronous, Single-Threaded language** — it can only execute one command at a time, in a specific order.

---

## 1.2 Global Execution Context (GEC)

The **Global Execution Context** is the first EC created when JavaScript starts running.

**Key characteristics:**

- Created automatically when the JS engine starts
- Contains the **Global Object** (`window` in browsers, `global` in Node.js)
- The special `this` keyword points to the global object _(in non-strict mode)_
- Holds all **variables and functions declared at the global scope**
- There is only **one** GEC per program

---

## 1.3 Function Execution Context (FEC)

A **Function Execution Context** is created **every time a function is invoked**.

**Key characteristics:**

- Each function call gets its **own** execution context
- Contains:
  - Function arguments
  - Local variables
  - Inner function declarations
- Multiple FECs can exist simultaneously (each on the call stack)

---

## 1.4 Execution Context Phases

Every Execution Context goes through **2 phases**:

### Phase 1 — Memory Creation Phase (Hoisting)

In this phase, the JS engine **skims through the entire program line by line** and allocates memory **before** any code runs.

| Variable/Function | Value Stored                      |
| ----------------- | --------------------------------- |
| Variables (`var`) | `undefined`                       |
| Functions         | Entire function definition stored |

**What happens:**

1. JS scans the whole program from top to bottom
2. Memory is reserved for every variable and function found
3. Variables get assigned `undefined` as a placeholder
4. Functions get their **entire body** stored in memory

### Phase 2 — Code Execution Phase

In this phase, JS **skims through the code again**, line by line, and **executes** it.

**What happens:**

1. Actual values are assigned to variables (replacing `undefined`)
2. Functions are invoked when called
3. When a function is called → a **new Execution Context** is created for it
4. After execution completes → the Execution Context is **deleted**

### Execution Context Lifecycle Example

```js
var n = 2

function square(num) {
  var ans = num * num
  return ans
}

var square2 = square(n)
var square4 = square(4)
```

![How Code Works](/assets/how_code_work.png)

**Memory Creation Phase walkthrough:**

| Identifier | Memory Value        |
| ---------- | ------------------- |
| `n`        | `undefined`         |
| `square`   | `{ function body }` |
| `square2`  | `undefined`         |
| `square4`  | `undefined`         |

**Code Execution Phase walkthrough:**

| Step                      | Action                                                 |
| ------------------------- | ------------------------------------------------------ |
| `var n = 2`               | `n` updated from `undefined` → `2`                     |
| `square(n)` called        | New FEC created; `ans = 4`; returns `4`; FEC deleted   |
| `var square2 = square(n)` | `square2` updated → `4`                                |
| `var square4 = square(4)` | New FEC created; `ans = 16`; returns `16`; FEC deleted |

## 1.5 Call Stack

The **Call Stack** manages the order of Execution Contexts.

![Call Stack Diagram](/assets/call_stack.png)

**How it works:**

- When a JS program runs, the **GEC is pushed onto the stack** first (bottom)
- Every time a **function is invoked**, a new **FEC is pushed** on top
- When a function **finishes executing**, its FEC is **popped off** the stack
- When the entire program finishes, the **GEC is also popped off**

**Call Stack visualization:**

```
┌──────────────┐
│     FEC      │  ← function currently executing (top)
├──────────────┤
│     FEC      │  ← calling function (waiting)
├──────────────┤
│     GEC      │  ← always at the bottom
└──────────────┘
```

> The Call Stack is also called: **Execution Context Stack**, **Program Stack**, **Control Stack**, **Runtime Stack**, or **Machine Stack**.

---

## 1.6 Stack Overflow

A **Stack Overflow** occurs when the call stack exceeds its size limit.

**Common cause — Infinite Recursion:**

```js
function recurse() {
  recurse() // calls itself endlessly
}
recurse() // ❌ RangeError: Maximum call stack size exceeded
```

**Why it happens:**

- Each function call pushes a new FEC onto the stack
- If a function never returns, the stack keeps growing
- Eventually the stack runs out of memory → **Stack Overflow error**

**How to avoid:**

- Always define a **base case** in recursive functions
- Ensure recursive calls converge toward the base case

```js
// ✅ Correct recursion with base case
function factorial(n) {
  if (n === 0) return 1 // base case — stops recursion
  return n * factorial(n - 1)
}
```

## Summary

| Concept           | Key Point                                                        |
| ----------------- | ---------------------------------------------------------------- |
| Execution Context | Environment where JS code runs; has Memory + Code components     |
| Global EC (GEC)   | Created once on program start; holds global scope                |
| Function EC (FEC) | Created per function call; holds local scope                     |
| Memory Phase      | Allocates memory; variables → `undefined`, functions → full body |
| Execution Phase   | Runs code line by line; assigns values; creates/destroys FECs    |
| Call Stack        | Tracks active ECs; GEC at bottom, FECs stacked on top            |
| Stack Overflow    | Call stack limit exceeded; usually from infinite recursion       |
