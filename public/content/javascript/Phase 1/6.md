# Hoisting in JavaScript

> **Hoisting** is the phenomenon in JavaScript by which we can access a variable or function **even before it has been initialized or declared** in the code.

This is possible because of the **Memory Creation Phase** of the Execution Context — before any code runs, JS allocates memory for all variables and functions.

**Quick Example:**

```js
getName();           // ✅ Output: "Hello World"
console.log(x);     // ✅ Output: undefined
console.log(getName); // ✅ Prints the entire function body

var x = 7;
function getName() {
    console.log("Hello World");
}
```

**Output:**
```
Hello World
undefined
ƒ getName() { console.log("Hello World"); }
```

> 💡 During the Memory Creation Phase, all variables and functions are stored under the **`window` (global) object**. Variables get `undefined`, functions get their entire body.

```
Global
  └── window (global object)
        ├── variables  →  undefined
        └── functions  →  entire function definition
```

---

## 1.1 Variable Hoisting — `var`, `let`, `const`

### `var` — Hoisted and Initialized as `undefined`

| Property | Behavior |
|---|---|
| Hoisted? | ✅ Yes |
| Initialized to | `undefined` |
| Accessible before declaration? | ✅ Yes (value is `undefined`) |
| Stored in | Global / `window` object |

```js
console.log(x); // ✅ undefined  (NOT an error)
var x = 10;
console.log(x); // 10
```

**What JS does internally:**
```js
// Memory Phase  →  var x = undefined
// Execution Phase → x = 10
```

---

### `let` and `const` — Hoisted but NOT Initialized

| Property | `let` | `const` |
|---|---|---|
| Hoisted? | ✅ Yes | ✅ Yes |
| Initialized to | ❌ Nothing (TDZ) | ❌ Nothing (TDZ) |
| Accessible before declaration? | ❌ ReferenceError | ❌ ReferenceError |
| Stored in | Separate script scope | Separate script scope |
| Must be initialized at declaration? | No | ✅ Yes |

```js
console.log(a); // ❌ ReferenceError: Cannot access 'a' before initialization
let a = 20;
```

```js
console.log(b); // ❌ ReferenceError: Cannot access 'b' before initialization
const b = 50;
```

> ⚠️ `let` and `const` are stored in a **separate memory space** (labelled `script` in DevTools), **not** in the global `window` object. This memory space cannot be accessed until a value has been assigned.

---

## 1.2 Function Hoisting

### Function Declarations — Fully Hoisted ✅

The **entire function body** is hoisted to the top of the scope.

```js
greet(); // ✅ Works perfectly — Output: "Hello"

function greet() {
    console.log("Hello");
}
```

> The whole function is stored in memory during the Memory Creation Phase, so it can be called **anywhere** in the code — even before its definition.

**Verifying with `console.log`:**

```js
console.log(getName); 
// Output: ƒ getName() { console.log("Hello World"); }
// Entire function body is printed — not undefined

function getName() {
    console.log("Hello World");
}
```

---

### Function Expressions & Arrow Functions — NOT Fully Hoisted ❌

When a function is assigned to a variable, it behaves **like a variable** — only the variable declaration is hoisted, not the function itself.

```js
sayHi(); // ❌ TypeError: sayHi is not a function
var sayHi = function() {
    console.log("Hi");
};
```

```js
greetUser(); // ❌ TypeError: greetUser is not a function
var greetUser = () => console.log("Hello User");
```

**What JS does internally:**
```js
// Memory Phase  →  var sayHi = undefined
// Execution Phase → sayHi = function() { ... }
// Calling sayHi() before line 2 → TypeError (undefined is not a function)
```

| Function Type | Variable Hoisted | Function Body Hoisted | Call Before Declaration |
|---|---|---|---|
| `function declaration` | ✅ | ✅ Full body | ✅ Works |
| `var` + function expression | ✅ (`undefined`) | ❌ | ❌ TypeError |
| `var` + arrow function | ✅ (`undefined`) | ❌ | ❌ TypeError |
| `let`/`const` + arrow function | ✅ (TDZ) | ❌ | ❌ ReferenceError |

---

## 1.3 Temporal Dead Zone (TDZ)

The **Temporal Dead Zone** is the time period between:

1. **When `let`/`const` is hoisted** (start of scope / block) → memory allocated, but empty
2. **When the actual declaration line is reached** → value assigned, TDZ ends

```
Code starts
    │
    │  ← TDZ begins (let/const hoisted into separate memory, no value)
    │
    │  console.log(a);   ← ❌ ReferenceError — still in TDZ
    │
    │  let a = 20;       ← ✅ TDZ ends here, value assigned
    │
    │  console.log(a);   ← ✅ 20
```

```js
console.log(a); // ❌ ReferenceError: Cannot access 'a' before initialization
let a = 20;
var b = 1000;   // ✅ No error — var is initialized as undefined
```

### Why does TDZ exist?

`let` and `const` are stored in a **separate memory space** from the global object. This space exists but JS **deliberately blocks access** to it until the declaration line is reached — to prevent bugs from accessing uninitialized variables.

```
Memory spaces during execution:

Global Object (window)          Script (separate space)
├── b: 1000                     ├── a: <uninitialized>  ← TDZ
└── ...                         └── ...
```

### `const` is even stricter than `let`

```js
const c; // ❌ SyntaxError: Missing initializer in const declaration
```

`const` must be **initialized at the time of declaration** — you cannot declare it first and assign later.

```js
const PI = 3.14;  // ✅
PI = 3.15;        // ❌ TypeError: Assignment to constant variable
```

## 1.4 Interview Questions — Predict the Output

### Question 1

```js
console.log(a);
var a = 5;
console.log(a);
```

<details>
<summary>Answer</summary>

```
undefined
5
```
`var a` is hoisted and initialized as `undefined`. After `a = 5` executes, it becomes `5`.

</details>

---

### Question 2

```js
console.log(b);
let b = 10;
```

<details>
<summary>Answer</summary>

```
ReferenceError: Cannot access 'b' before initialization
```
`let` is in the TDZ until line 2. Accessing it before that throws a ReferenceError.

</details>

---

### Question 3

```js
sayHello();
function sayHello() {
    console.log("Hello!");
}
```

<details>
<summary>Answer</summary>

```
Hello!
```
Function declarations are fully hoisted — the entire body is available before the declaration line.

</details>

---

### Question 4

```js
greet();
var greet = function() {
    console.log("Hi");
};
```

<details>
<summary>Answer</summary>

```
TypeError: greet is not a function
```
Only `var greet = undefined` is hoisted. Calling `undefined()` throws a TypeError.

</details>

---

### Question 5

```js
console.log(x);
console.log(y);
var x = 1;
let y = 2;
```

<details>
<summary>Answer</summary>

```
undefined
ReferenceError: Cannot access 'y' before initialization
```
`var x` → hoisted as `undefined`. `let y` → in TDZ, throws ReferenceError. Code stops at line 2.

</details>

---

### Question 6

```js
getName();
console.log(x);
console.log(getName);

var x = 7;
var getName = () => console.log("Arrow Function");

function getName() {
    console.log("Hello World");
}
```

<details>
<summary>Answer</summary>

```
Hello World
undefined
ƒ getName() { console.log("Hello World"); }
```

- `getName()` → the **function declaration** is hoisted fully, so it runs ✅
- `console.log(x)` → `var x` is `undefined` at this point
- `console.log(getName)` → still points to the **function declaration** (the arrow function assignment hasn't run yet)
- After execution reaches `var getName = () => ...`, `getName` gets overwritten with the arrow function

</details>

---

### Question 7 — Tricky TDZ

```js
let x = 1;
{
    console.log(x);
    let x = 2;
}
```

<details>
<summary>Answer</summary>

```
ReferenceError: Cannot access 'x' before initialization
```
Inside the block, the inner `let x` is hoisted to the top of the **block scope** and enters TDZ. Even though the outer `x = 1` exists, the inner declaration shadows it — and since it's in TDZ, accessing it throws a ReferenceError.

</details>

## Summary

| | `var` | `let` | `const` | Function Declaration | Function Expression / Arrow |
|---|---|---|---|---|---|
| Hoisted? | ✅ | ✅ | ✅ | ✅ | ✅ (variable only) |
| Initialized? | `undefined` | ❌ TDZ | ❌ TDZ | Full body | `undefined` (if var) / TDZ (if let/const) |
| Scope | Function / Global | Block | Block | Function / Global | Depends on variable type |
| Access before declaration | `undefined` | ReferenceError | ReferenceError | ✅ Works | TypeError / ReferenceError |
| Re-assignable? | ✅ | ✅ | ❌ | ✅ | ✅ |
| Re-declarable? | ✅ | ❌ | ❌ | ✅ | Depends |
