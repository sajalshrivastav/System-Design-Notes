# Scope & Scope Chain in JavaScript

> **Scope** determines the **accessibility (visibility) of variables** — where in your code a variable can be read or written.

JavaScript uses **Lexical Scoping**, meaning scope is determined at **write time** (where you physically write the code), not at runtime.

---

## 1.1 Global Scope

A variable is in **Global Scope** when it is declared **outside of any function or block**.

- Accessible from **anywhere** in the program
- Attached to the **global object** (`window` in browsers, `global` in Node.js)
- `var` declarations at the top level become properties of `window`

```js
var globalVar = "I am global";
let globalLet = "Also global (but not on window)";

function show() {
    console.log(globalVar); // ✅ Accessible
    console.log(globalLet); // ✅ Accessible
}

show();
console.log(window.globalVar); // ✅ "I am global"
console.log(window.globalLet); // ❌ undefined (let is NOT on window)
```

> ⚠️ **Avoid polluting the global scope.** Too many global variables cause naming conflicts and hard-to-track bugs.

### Global Scope Pollution Example

```js
var count = 0; // global — any function can accidentally overwrite it

function increment() {
    count++; // modifies global — side effect!
}

function reset() {
    count = 0; // overwrites global — dangerous in large codebases
}
```

---

## 1.2 Function Scope

Variables declared **inside a function** are scoped to that function — they cannot be accessed from outside.

- Each function creates its **own scope**
- `var`, `let`, and `const` declared inside a function are all function-scoped
- Function parameters are also function-scoped

```js
function greet() {
    var message = "Hello!";
    let name = "Alice";
    console.log(message); // ✅ "Hello!"
    console.log(name);    // ✅ "Alice"
}

greet();
console.log(message); // ❌ ReferenceError: message is not defined
console.log(name);    // ❌ ReferenceError: name is not defined
```

### Each Function Call Gets Its Own Scope

```js
function counter() {
    var count = 0;
    count++;
    console.log(count);
}

counter(); // 1
counter(); // 1  ← fresh scope each call, count resets
counter(); // 1
```

> 💡 Every time a function is **invoked**, a brand new **Function Execution Context** is created with its own memory — variables start fresh.

---

## 1.3 Block Scope

A **block** is any code wrapped in `{ }` — `if`, `for`, `while`, or just a standalone block.

- `let` and `const` are **block-scoped** — they exist only within the `{ }` they are declared in
- `var` is **NOT block-scoped** — it leaks out of blocks into the enclosing function/global scope

```js
{
    let blockLet = "I am block scoped";
    const blockConst = "Me too";
    var blockVar = "I leak out!";
}

console.log(blockVar);   // ✅ "I leak out!"  (var ignores block)
console.log(blockLet);   // ❌ ReferenceError
console.log(blockConst); // ❌ ReferenceError
```

### `var` Leaking in Loops — Classic Bug

```js
// ❌ Using var — leaks out, shares one variable
for (var i = 0; i < 3; i++) {
    setTimeout(() => console.log(i), 100);
}
// Output: 3, 3, 3  (all share the same i)

// ✅ Using let — new binding per iteration
for (let j = 0; j < 3; j++) {
    setTimeout(() => console.log(j), 100);
}
// Output: 0, 1, 2  (each iteration has its own j)
```

### `var` vs `let`/`const` — Scope Comparison

```js
function testScope() {
    if (true) {
        var x = 10;   // function-scoped → available outside if block
        let y = 20;   // block-scoped → only inside if block
        const z = 30; // block-scoped → only inside if block
    }
    console.log(x); // ✅ 10
    console.log(y); // ❌ ReferenceError
    console.log(z); // ❌ ReferenceError
}
```

## 1.4 Lexical Scope

**Lexical Scope** means that the scope of a variable is determined by **where it is written in the source code** — specifically, by the **position of its declaration** relative to the surrounding functions and blocks.

> Inner functions have access to variables of their **outer (parent) functions** — this is decided at **write time**, not call time.

```js
function outer() {
    let outerVar = "I am from outer";

    function inner() {
        console.log(outerVar); // ✅ Can access parent's variable
    }

    inner();
}

outer(); // Output: "I am from outer"
```

### Lexical Scope is Static

The scope is fixed based on **where the function is defined**, not where it is called.

```js
let name = "Global";

function printName() {
    console.log(name); // looks up from where printName is DEFINED
}

function outer() {
    let name = "Outer";
    printName(); // even though called inside outer(), printName sees "Global"
}

outer(); // Output: "Global"  ← NOT "Outer"
```

> `printName` was **defined** in the global scope, so it looks up `name` from the global scope — not from `outer`'s scope where it was called.

## 1.5 Scope Chain

When JavaScript looks up a variable, it searches through a chain of scopes — starting from the **innermost** scope and moving **outward** until it finds the variable or reaches the global scope.

This chain of scopes is called the **Scope Chain**.

### How the Scope Chain Lookup Works

```
Variable lookup order:
  Current scope
      ↓  (not found?)
  Parent scope
      ↓  (not found?)
  Grandparent scope
      ↓  (not found?)
  ...
  Global scope
      ↓  (not found?)
  ReferenceError ❌
```

### Scope Chain Example

```js
var globalVar = "global";

function outer() {
    var outerVar = "outer";

    function middle() {
        var middleVar = "middle";

        function inner() {
            var innerVar = "inner";

            // Inner can access ALL scopes above it
            console.log(innerVar);  // ✅ "inner"   → found in own scope
            console.log(middleVar); // ✅ "middle"  → found in middle's scope
            console.log(outerVar);  // ✅ "outer"   → found in outer's scope
            console.log(globalVar); // ✅ "global"  → found in global scope
        }

        inner();

        // middle CANNOT access inner's variables
        console.log(innerVar); // ❌ ReferenceError
    }

    middle();
}

outer();
```

**Scope chain visualization:**

```
Global Scope
│   globalVar = "global"
│
└── outer()
    │   outerVar = "outer"
    │
    └── middle()
        │   middleVar = "middle"
        │
        └── inner()
                innerVar = "inner"
                ↑ can see all of the above
```

> 🔑 **Key rule:** Scope chain only goes **upward (outward)** — a child scope can access parent scopes, but a parent **cannot** access a child's scope.

### Variable Shadowing in Scope Chain

When a variable in an inner scope has the **same name** as one in an outer scope, the inner one **shadows** the outer one.

```js
let x = "global x";

function outer() {
    let x = "outer x"; // shadows global x

    function inner() {
        let x = "inner x"; // shadows outer x
        console.log(x);    // ✅ "inner x"
    }

    inner();
    console.log(x); // ✅ "outer x"  (inner's x doesn't affect this)
}

outer();
console.log(x); // ✅ "global x"
```

## 1.6 Interview Questions — Nested Scope Resolution

### Question 1 — Basic Scope Chain

```js
var a = 1;

function outer() {
    var b = 2;
    function inner() {
        var c = 3;
        console.log(a); // ?
        console.log(b); // ?
        console.log(c); // ?
    }
    inner();
    console.log(c); // ?
}

outer();
```

<details>
<summary>Answer</summary>

```
1        ← a found in global scope
2        ← b found in outer's scope
3        ← c found in inner's own scope
ReferenceError: c is not defined  ← outer cannot see inner's c
```

</details>

---

### Question 2 — `var` vs `let` in Block Scope

```js
function test() {
    var x = 1;
    if (true) {
        var x = 2;    // same variable (var is function-scoped)
        let y = 3;
        console.log(x); // ?
        console.log(y); // ?
    }
    console.log(x); // ?
    console.log(y); // ?
}
test();
```

<details>
<summary>Answer</summary>

```
2     ← var x inside if, same x as outer (function-scoped)
3     ← let y inside its block ✅
2     ← var x was overwritten to 2
ReferenceError: y is not defined  ← let y was block-scoped to the if block
```

</details>

---

### Question 3 — Lexical Scope vs Call Scope

```js
let env = "global";

function showEnv() {
    console.log(env);
}

function outer() {
    let env = "outer";
    showEnv(); // ?
}

outer();
```

<details>
<summary>Answer</summary>

```
global
```
`showEnv` is **defined** in the global scope. Even though it's **called** from inside `outer`, it looks up `env` from where it was written — the global scope. This is the core of **lexical scoping**.

</details>

---

### Question 4 — Variable Shadowing

```js
let value = "top";

function first() {
    let value = "first";
    function second() {
        console.log(value); // ?
    }
    second();
}

function third() {
    console.log(value); // ?
}

first();
third();
```

<details>
<summary>Answer</summary>

```
first   ← second() looks up scope chain, finds value = "first" in first()
top     ← third() is defined in global scope, finds global value = "top"
```

</details>

### Question 5 — Scope Chain with Closures

```js
function makeCounter() {
    let count = 0;
    return function() {
        count++;
        console.log(count);
    };
}

const counter = makeCounter();
counter(); // ?
counter(); // ?
counter(); // ?
```

<details>
<summary>Answer</summary>

```
1
2
3
```
The returned function **closes over** `count` via the scope chain. Even after `makeCounter` has finished executing, the inner function retains access to `count` through the scope chain — this is a **closure**.

</details>

### Question 6 — Tricky `var` in Loop

```js
for (var i = 0; i < 3; i++) {
    setTimeout(function() {
        console.log(i);
    }, 0);
}
```

<details>
<summary>Answer</summary>

```
3
3
3
```
`var i` is function-scoped (or global here), so all three callbacks share the **same `i`**. By the time the callbacks run, the loop has finished and `i === 3`.

**Fix using `let`:**
```js
for (let i = 0; i < 3; i++) {
    setTimeout(() => console.log(i), 0);
}
// Output: 0, 1, 2  ✅
```

</details>

### Question 7 — Nested Scope Resolution

```js
let x = 10;

function foo() {
    let x = 20;
    function bar() {
        let x = 30;
        function baz() {
            console.log(x); // ?
        }
        baz();
        x = 35;
        baz();
    }
    bar();
}

foo();
```

<details>
<summary>Answer</summary>

```
30
35
```
`baz` finds `x` in `bar`'s scope (nearest parent). First call → `x = 30`. After `x = 35`, second call → `x = 35`. Note: `baz` doesn't find a new `x` each time — it references `bar`'s `x` live.

</details>

## Summary

| Scope Type | Created by | Accessible from | `var` | `let` / `const` |
|---|---|---|---|---|
| **Global** | Top-level code | Anywhere | ✅ on `window` | ✅ (not on `window`) |
| **Function** | `function () {}` | Inside that function only | ✅ | ✅ |
| **Block** | `{ }` any block | Inside that block only | ❌ leaks out | ✅ stays inside |
| **Lexical** | Nesting structure | Inner → outer (not reverse) | ✅ | ✅ |

### Scope Chain Rules — Quick Reference

```
✅ Inner scope CAN access outer scope variables
❌ Outer scope CANNOT access inner scope variables
✅ Lookup goes: own scope → parent → grandparent → ... → global
❌ If not found anywhere → ReferenceError
✅ Inner variable SHADOWS outer variable of same name
✅ Scope is determined at WRITE TIME (lexical), not call time
```
